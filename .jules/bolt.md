## 2024-06-28 - [Combine Root Entities Fetch in Bootstrap Path]
**Learning:** The `getBootstrapData` method is the primary data payload initialization path for the UI. Previously, it fetched root entities (groups, bookings, clients, staff, transactions, inventory, tenant) sequentially. This caused significant database round-trip latency, especially pronounced with SQLite disk synchronization. Additionally, it relied on a nested loop to query `channelMappings` and `icalConnections` for every individual unit, triggering an N+1 query vulnerability.
**Action:** Always combine independent, disjoint queries into a single `Promise.all` invocation to allow the database to resolve them concurrently. To resolve nested relationship fetches without loading unnecessary parent graphs into memory, collect child IDs using `.flatMap` and issue a single grouped query utilizing the Prisma `in` operator.
