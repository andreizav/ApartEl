## 2023-10-27 - Refactor `getBootstrapData` sequential queries into a single `Promise.all`
**Learning:** Sequential Prisma queries without inter-dependencies dramatically increase API response times due to cumulative database connection round-trips. Furthermore, iterating over collections and executing separate relation queries (like fetching channel mappings inside a loop over units) generates severe N+1 performance penalties.
**Action:** Always inspect bulk read endpoints (like bootstrap loaders) for sequence patterns. Batch independent Prisma queries with `Promise.all()` to resolve concurrently. For nested collections, query from the "child" upwards with nested relation filters (e.g., `where: { unit: { group: { tenantId } } }`) to resolve data in O(1) database queries instead of O(N).
