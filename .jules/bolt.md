## 2024-05-18 - [Optimizing getBootstrapData sequential and nested queries]
**Learning:** Sequential, independent database queries inside a widely-used method like `getBootstrapData` artificially bottleneck application startup and response times. Fetching related models dynamically inside loops (like fetching `channelMappings` and `icalConnections` per `unit` inside a `group` loop) creates a classic N+1 query issue, increasing database load linearly with data size. Prisma handles arrays perfectly via the `in` operator even if they are empty, so bulk querying relation data requires no edge case handling when no relational entity exists.
**Action:** Always group independent Prisma queries into `Promise.all()` to fetch them concurrently. Extract related entity lookups inside loops into a single array using `flatMap` or mapping strategies, then use the `in` operator (e.g. `where: { id: { in: extractedIds } }`) to bulk-load data in a single request, remapping them to parents in application memory if nested structures are needed.
