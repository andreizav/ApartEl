## 2025-05-04 - Backend Concurrent Data Fetching Optimization
**Learning:** The initial application data fetch in NestJS (`getBootstrapData`) was querying multiple independent Prisma models sequentially using `await` lines, resulting in blocked execution paths and a high cumulative network latency. The `channelMappings` and `icalConnections` were fetched using an N+1 loop pattern per group/unit.
**Action:** Always fetch mutually independent root entities concurrently using `Promise.all` in initial data payload routes. For nested entities tied to relations (like units), avoid looping over arrays and instead flatten identifiers (e.g., `flatMap` to collect `unitIds`) to perform single bulk database queries using the Prisma `in` operator (e.g., `where: { unitId: { in: unitIds } }`).
