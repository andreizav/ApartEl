## 2024-06-26 - Optimized getBootstrapData Queries\n**Learning:** The `getBootstrapData` method is the critical initialization path for the frontend and had multiple sequential `await` calls and an N+1 query inside a loop for relations, which slows down application start times. Fetching independent entities concurrently using `Promise.all` and extracting IDs for a single batch query significantly reduces database round-trip delays.\n**Action:** Always audit large initialization payloads (like `getBootstrapData` or `seedTenantData`) for sequential `await` statements and loop-based queries. Convert them to `Promise.all` and `where: { in: [...] }` queries early in development to ensure smooth scaling.
