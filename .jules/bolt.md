## 2024-03-10 - Prisma Relationship Queries instead of Map/Reduce nested models
**Learning:** Found a major N+1 query and mapping anti-pattern in `getMappings` and `getIcal`. The existing code fetched a massive tree structure `tenant -> groups -> units -> relations` simply to aggregate all relations into a single array using nested O(N^3) `forEach` loops. Fetching and instantiating large nested trees in Prisma causes massive memory overhead and slow query response times.
**Action:** When a flat list of relations is needed for a specific root entity (e.g. all mappings for a tenant), query the target model directly using Prisma's nested relation filters `findMany({ where: { unit: { group: { tenantId } } } })` rather than fetching the top-level entity and traversing down the tree manually.
