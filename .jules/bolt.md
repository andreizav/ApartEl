## 2024-05-18 - [SQLite Case-Insensitive Queries]
**Learning:** SQLite doesn't natively support `mode: 'insensitive'` in Prisma for case-insensitive string filtering. The codebase was fetching all staff records (`await this.prisma.staff.findMany()`) into memory and filtering them by `s.email.toLowerCase() === email.toLowerCase()` in `auth.service.ts` and `staff.service.ts`, leading to an O(N) memory and compute bottleneck on login, registration, and staff creation.
**Action:** Instead of application-side filtering, use Prisma's `$queryRaw` with `LOWER()` function (e.g., `await this.prisma.$queryRaw<Staff[]>\`SELECT * FROM "Staff" WHERE LOWER(email) = LOWER(${email})\``) to leverage the database engine and avoid O(N) full-table data transfer. Remember that boolean fields returned by `$queryRaw` in SQLite are 0 or 1, and may need casting to booleans.
